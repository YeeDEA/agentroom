# PRD: 초경량 실시간 AI 위변조 판별 API (Anti-AI Fraud Shield)

- 작성 기준 문서: `트랙3. AI 비즈니스 랩_사업 기획안_최용준_2022142031.pdf`
- 작성일: 2026-07-09

## 1. 배경 및 문제 정의

생성형 AI(딥페이크, 이미지 합성)의 대중화로 중고거래 플랫폼(당근마켓, 중고나라, 번개장터 등)에서
"존재하지 않는 물품 사진", "위조 영수증", "실시간 변조 화상통화"를 이용한 사기가 늘고 있다.
기존 보안 대기업의 Vision Transformer 기반 탐지는 건당 비용이 높아, 하루 수천만 건이 업로드되는
C2C 플랫폼에는 재무적으로 적용이 불가능하다.

**핵심 가설**: 픽셀 단위 주파수 왜곡(FFT 기반 격자 노이즈) 분석으로 전체 이미지를 분석하지 않고도
생성형 AI 산출물을 초저비용·초저지연으로 판별할 수 있다.

## 2. 목표 (Goals)

1. 2주 안에 "중고거래 판매자가 업로드한 이미지가 AI로 위변조되었는가"를 판별하는 API/봇의
   실사용 수요를 정량적으로 검증한다.
2. 플랫폼(B2B)이 실제로 지불 의사가 있는 최소 가격대(건당 과금)를 확인한다.
3. 기술적으로 서버리스(CPU) 환경에서 목표 지연시간 내 동작하는 프로토타입을 만든다.

## 3. 비목표 (Non-goals, 이번 스프린트 기준)

- 웨어러블 SDK 라이선스 사업화 (2단계 이후로 연기)
- 정식 결제/PG 연동 (검증 단계에서는 결제 의向만 확인)
- 프로덕션 수준의 오탐률 튜닝

## 4. 타깃 사용자

- **1차**: 트래픽 변동이 큰 C2C 중고거래 플랫폼 운영사/개발팀 (B2B API 구매자)
- **2차**: 전문 중고 판매자·소상공인 (구독형 SaaS 사용자)

## 5. 핵심 기능 요구사항

| 기능 | 설명 | 우선순위 |
|---|---|---|
| 이미지 업로드 판별 API | 이미지 1장을 받아 위변조 확률(0~1)과 신뢰도를 반환 | P0 |
| 응답 지연 예산 | 목표 응답시간 명시 및 실측치 공개 (아래 개선점 참고) | P0 |
| 사용량 기반 과금 로그 | 호출 건수·응답시간을 기록해 원가/과금 근거 데이터 확보 | P0 |
| 얼리엑세스 랜딩페이지 | 문제·해결책 설명 + 이메일 수집으로 수요 검증 | P0 |
| 디스코드 체험 봇 | 실사용자가 이미지를 올려 즉시 판별 결과를 받는 체험 흐름 | P1 |

## 6. 성공 지표 (현실화된 버전)

원본 기획서의 지표는 검증 없이 과장된 수치가 섞여 있어 아래와 같이 재정의한다.

- **수요**: 랜딩페이지 순 방문자 300명, 이메일 등록 전환 5% 이상
- **기술**: 실측 P95 응답시간을 공개 (목표 수치가 아니라 측정값), 처리 실패율 0%
- **매출 의向**: "결제 페이지 클릭"과 "실제 결제 완료"를 분리 집계 — 결제 완료 없이 매출 지표로
  혼용하지 않는다.

## 7. 원본 기획서 개선점 (Critical Review)

1. **검증되지 않은 수치 남발**: "92% 연산 소거", "건당 0.3원", "지연 20ms" 등이 구체적 벤치마크
   근거 없이 제시됨. → PRD에서는 실측 전까지 목표치(target)와 실측치(measured)를 분리 표기해야 한다.

2. **사업모델이 3갈래로 분산**: B2B 종량제·C2C 구독·웨어러블 SDK를 동시에 추진하면 2주 검증 기간
   내 어느 것도 제대로 검증하지 못한다. → 이번 스프린트는 **B2B 종량제 API 한 가지**에 집중하고
   나머지는 로드맵으로 이동.

3. **결제 검증 방식의 리스크**: "실제 카드 정보 입력 팝업"으로 결제 유도를 실험하는 것은 PG(전자
   결제대행) 등록 없이 결제를 받는 행위로 법적 문제가 될 수 있고, 사용자를 오도하는 다크패턴이다.
   → 실제 결제 없이 "사전예약(웨이트리스트) + 가격 제시 후 반응 확인"으로 대체해야 한다.

4. **민감 대상 리서치 설계 미흡**: "실제 사기 피해자 커뮤니티" 40명을 1주 안에 FGI 하겠다는 계획은
   피해자에게 재트라우마를 줄 수 있고, 동의 절차·개인정보 처리 방침이 없다. → 대상을 "중고거래
   플랫폼 운영/CS 담당자"로 좁히고 규모를 10~15명으로 축소, 사전 동의서를 마련한다.

5. **기술 리스크 섹션 부재**: FFT 기반 격자 노이즈 탐지는 초기 GAN/Diffusion 모델의 특징이며,
   최신 Latent Diffusion·후처리(리사이즈, 압축) 모델은 이 흔적이 옅어질 수 있다. 이 기술적 한계에
   대한 검증 계획이 기획서에 없다. → PRD에 "최신 생성모델 5종에 대한 탐지율 벤치마크"를 P0 항목으로
   추가해야 한다.

6. **경쟁 분석이 해외 대기업(Reality Defender)에만 한정**: 국내 플랫폼(당근마켓 자체 필터, 업스
   테이지 등 국내 딥페이크 탐지 스타트업)과의 비교가 없어 시장 진입 난이도를 과소평가할 위험이 있다.

7. **개인정보/법적 컴플라이언스 언급 없음**: 사용자가 업로드하는 이미지에는 개인정보가 포함될 수
   있어 개인정보보호법(PIPA) 상 처리방침, 보관기간, 삭제 정책이 필요하다.

8. **고정비 "0원" 주장의 근거 부족**: 서버리스 호출 비용은 0에 가까울 수 있지만, 도메인/모니터링/
   법인 운영비 등 실제 고정비가 존재한다. → 비용 구조표에 이 항목들을 명시해야 한다.

## 8. v2 — 증거 기반 판별 아키텍처 (2026-07-15 갱신)

멘토 피드백("하나의 확률로 단정하지 말고 증거를 분리해 제시하라, 실측 수치를 공개하라")과
"쉬운 언어·체험 확대·구조적 차별성" 방향을 반영한 2차 개선.

### 8.1 증거 분리 원칙
- 단일 확률 폐기 → 독립 검사 3종(촬영 정보 메타데이터 / 주파수 결 분석 / 재압축 오차 ELA)이
  각자 신호(0~1 또는 판단불가 null)와 **판단 근거**를 쉬운 한국어로 제시.
- 종합 판정은 신호등(🟢 특이점 없음 / 🟡 확인 필요 / 🔴 의심 정황 다수) + "N개 검사 중 M개에서
  의심 신호" 요약. 단정 표현 금지.

### 8.2 플러그인 아키텍처 (Gemini 연동 완료)
- `public/evidence/` 폴더에 공통 인터페이스(`analyze(ctx) → EvidenceReport`)를 갖는 분석기 모듈.
- `registry.js`에 분석기를 추가하면 UI 카드가 자동 확장.
- 검사 5종으로 확장 (v2.1): ①메타데이터 ②주파수 결 ③재압축 오차(ELA) ④카메라 센서 흔적
  (CFA 주기성·채널 노이즈 독립성·잔여 노이즈 첨도) ⑤**Gemini 내용 정밀 분석**(글자 왜곡,
  그림자·원근 모순, 해부학적 이상, 질감 이상 — Firebase AI Logic, gemini-2.5-flash).
- Gemini는 종합 판정에서 2표 가중치. 콘솔에서 AI Logic 활성화 전에는 "사용 불가" 카드로
  안내 표시되며 나머지 4종 로컬 검사는 정상 동작.
- 랜딩의 미니 데모·즉석 벤치마크는 비용·지연 때문에 로컬 4종만 사용 (Gemini 제외).

### 8.3 체험 우선 설계
- 판별 페이지: 업로드 없이 원클릭 샘플 3종(일반 사진 느낌/AI 흔적/영수증 스타일, 브라우저가
  즉석 생성한 시뮬레이션임을 명시) 체험.
- 랜딩: 히어로 아래 미니 체험 위젯(샘플 2종 즉석 판정) + "왜 다른가" 2열 구조 비교 다이어그램.

### 8.4 벤치마크 투명성 정책
- 사용자가 자기 브라우저에서 직접 측정하는 즉석 벤치마크(합성 샘플 20장: 정탐률/오탐률/평균
  처리시간)를 제공. 합성 샘플 기준임을 명시하고, 실제 AI 생성물 벤치마크는 "검증 중"으로 구분.
- 비용도 "브라우저 데모 0원 / API 버전 목표치(검증 중)"로 분리 표기 — 측정값과 목표값 혼용 금지.

## 9. 로드맵

- **1주차**: 플랫폼 운영/CS 담당자 10~15명 인터뷰, 랜딩페이지 배포 및 트래픽 유입
- **2주차**: 디스코드 체험 봇 배포, 실측 지연시간/실패율 공개, 웨이트리스트 전환율 확인
- **3단계 (검증 통과 시)**: 최신 생성모델 벤치마크 확장, PG 연동 및 실제 결제 파일럿, C2C SaaS·
  웨어러블 SDK 순차 검토
