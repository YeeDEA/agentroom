# 디자인 거장 패널 (2026-08-12) — 3단 골격을 부수는 근거

6인 소집(달리·피카소·고흐·잡스·팀쿡·미란다). 서로 다른 언어로 **같은 결론**:
디스코드식 3단 레이아웃(레일+채널+채팅+펫 다이얼로그)은 이 제품의 본질(근거와 함께 답하는 팀 기억)을
세 번째 칸의 세입자로 처박았다. 색을 바꾸는 건 표면, 디자인은 구조를 다시 묻는 것.

## 각 관점 핵심
- **달리**: 시간을 위→아래로 흘리지 마라. 기억을 **안쪽에 쌓아라(나이테)** — 오래·자주 인용된 지식이 핵, 오늘 대화가 바깥 껍질. 백필=핵에 돋는 오래된 화석 고리.
- **피카소**: 채팅·위키·에이전트는 한 얼굴의 세 각도. **흐름(왼쪽)+응결(오른쪽) 이중 화면**, 승격되는 문장이 위키 면으로 접혀 들어가 두 곳에 동시 존재. 에이전트=두 면 사이 경첩. 각주=두 면을 잇는 힘줄.
- **고흐**: 배경이 미세하게 떨려야(옅은 radial 온기 한 귀퉁이). 카드 균질 금지 — 질문·답변·근거 여백을 12·20·16으로 다르게. 에이전트는 4초 호흡. **움직임은 300~500ms 한 번, 무한반복은 호흡 하나뿐, 흰 여백 60%+**.
- **잡스**: 첫 화면에서 덜어낼 3 = 펫 육성 패널·헤더 버튼줄(자율개입/요약/내보내기)·명령어 힌트. 키울 단 하나 = **근거 각주 답변 흐름**. 데모의 "와" = 각주 클릭→원본 대화 점프.
- **팀쿡**: 이모지가 브랜드를 대신함(OS별 렌더 상이·스크린리더·접근성 붕괴) → SVG 통일. title 툴팁 의존 금지(터치·키보드·SR 불가). 강조색 아껴야 강조. 화면당 주인공 하나. 빈화면/로딩/실패 상태를 컴포넌트로 표준화.
- **미란다**: 이모지→SVG는 취향 아니라 위생. 색 바꿈은 결정 아니라 기분. 애니메이션은 불안을 덮은 것. **프로가 목숨 거는 5가지**: ①타이포 위계(본문16/1.6·근거칩13/tabular·메타11/tracking) — 근거 각주가 본문과 같은 회색이면 유일한 차별점을 묻은 것 ②광학적 정렬(align-items:center 다음부터가 시작) ③여백 리듬(하나의 스페이싱 스케일, 간격이 명확한 비율로) ④색의 온도·목적(AI색/사람색/검증색/신뢰하락색 분리, warm/cool, 다크는 재계산) ⑤모션 이징(등장=ease-out, 클릭반응=120ms 단호, 시스템=240ms, `transition:all` 금지).

## 종합 → 실행 방향 (다음 라운드 골격 재설계)
1. **3단 → "질문·답변 중심 단일 캔버스".** 채널·에이전트는 상단 얇은 띠/칩으로 납작하게. 펫·명령어·헤더 버튼은 답변 후에만 등장.
2. **왼쪽 흐름 + 오른쪽 응결(위키)** 이중 구조 검토(피카소) — 승격이 위키로 접혀 들어가는 모션.
3. **타이포/스페이싱/색-의미/이징을 토큰으로 표준화**(미란다·팀쿡) — CSS 변수 스케일 1벌.
4. 배경 미세 온기 + 에이전트 4초 호흡(고흐), 그러나 흰 여백 60%+ 산뜻함 유지.
5. 접근성: aria-label + 보이는 포커스 링 + 빈/로딩/실패 상태 표준.

> 주의: 이건 GDG 4주 검증(코드 동결 원칙)과 별개의 '얼굴' 작업 — 시연 인상에 직결되므로 예외로 진행하되, 회수·계측·백필 로직은 건드리지 않는다.
